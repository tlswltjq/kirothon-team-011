# 화면 문구 점검과 제안 (UX 라이팅)

대상: `src/main/resources/static/{index,upload,review,my}.html`, `js/{nav,index,api,upload,review,my}.js`
기준 문서: `.kiro/steering/product.md`, `e2e/resume-flow.spec.cjs`, `e2e/demo.spec.cjs`
코드는 수정하지 않았다. 아래 "제안 문구"는 구현 담당이 반영할 초안이다.

## 0. 먼저 읽을 것: 요약

1. **말투가 섞여 있다.** 대부분 해요체인데 `review.js`·`review.html`·`my.html`·`api.js`와 서버 오류 메시지(`message` 필드)가 합니다체다. 서버 메시지는 `errorText()`가 그대로 화면에 띄우므로 사용자는 한 화면에서 두 말투를 본다. 해요체로 통일한다.
2. **사실과 다른 문구가 2개 있다. 데모에서 지적받기 쉽다.**
   - 랜딩 1단계 "이름·연락처·사진을 자동으로 찾아요"는 틀리다. 이름은 자동으로 찾지 않는다(upload.html "이름은 자동으로 찾지 않아요"와 모순). 자동은 이메일·전화번호·링크·사진이고, 이름은 사용자가 단어를 눌러 가린다.
   - 랜딩 안심 문구 "원본 PDF는 게시하면 바로 삭제"는 절반만 맞다. 게시하지 않은 초안은 24시간 뒤 삭제다.
3. **"저장되는 것은 가린 이미지뿐"은 그대로 쓰면 안 된다.** 서버에는 가린 이미지 외에 주인 전용 추출 텍스트와 가린 위치 목록도 남는다(product.md, 게시 완료 카드도 그렇게 안내한다). 데모의 핵심 메시지는 **평가자 시점**으로 쓴다: "평가자에게 보이는 것은 이름이 가려진 이미지뿐이에요." 저장 범위는 게시 완료 카드의 정확한 문장을 그대로 쓴다.
4. **용어가 흔들린다.** 마스킹/가림/가리기, 핀 코멘트/코멘트/첨삭, 글자/텍스트/글자 데이터, 공개/게시. 5절 용어집으로 고정한다.
5. 오류 문구는 "원인 + 할 일"이 대체로 갖춰져 있다. 빠진 곳(네트워크 오류, "입력을 확인해 주세요", "찾을 수 없어요")만 보강한다.
6. 조사 오류: 게시 완료 제목 `v2을 게시했어요`는 `v2를`이어야 한다(E2E 정규식과 호환, 6절).

## 1. 변경 금지 문구 (E2E 의존)

아래 문자열은 `e2e/resume-flow.spec.cjs`(핵심 흐름 E2E)와 `e2e/demo.spec.cjs`(녹화)가 화면 텍스트로 직접 찾는다. 바꾸면 테스트가 깨진다. 표의 "허용 범위"를 벗어나는 수정은 E2E도 함께 고쳐야 한다.

| # | 위치(파일 · 요소) | 의존 문구 | 테스트가 보는 방식 | 허용 범위 |
|---|---|---|---|---|
| E1 | index.html `main .big-btn` 2개 | `평가받기`, `평가하기` | `hasText` 부분 일치로 링크 선택. 두 링크의 `small` 설명에 서로의 단어(`평가받기`/`평가하기`)가 들어가면 두 링크가 동시에 걸려 오류가 난다. 랜딩 `main` 안에 `.big-btn`을 더 추가하지 않는다 | 제목 `strong`은 **변경 금지**. `small`만 변경 가능(상대 단어 금지) |
| E2 | index.html 전체 | `<input>` 0개 | 랜딩에 입력 칸이 없어야 한다 | 입력 칸 추가 금지 |
| E3 | upload.js `TYPE_LABELS` + `#summary` | `이메일 N`, `전화번호 N`, `링크 N`, `사진 N`, `지정 단어 N` (라벨, 공백 1칸, 숫자) | 정규식 `라벨 [1-9]\d*` | 라벨 5개와 "라벨 숫자" 형식 **변경 금지** |
| E4 | upload.js 게시 완료 `#done-title` | `v1을 게시했어요`, `v2를 게시했어요` 형태 | 정규식 `/v{N}.{1,2} 게시했어요/`. `v{N}` 바로 뒤에 1~2글자, 공백, `게시했어요` | 조사 `을/를`만 바꿀 수 있다. `v2 버전을 게시했어요`처럼 길게 쓰면 실패 |
| E5 | my.js 버전 행 `#version-list li` | `평가 보기`(버튼), `평균 4.00점`, `평균 5.00점`, `평가 없음` | `getByRole('button', {name:'평가 보기'})`(부분 일치), `toContainText` | 버튼명 `평가 보기`, `평균 N.NN점`, `평가 없음` **변경 금지** |
| E6 | my.js 상세 `#detail-title` | `v{N}` 포함 | `toContainText('v1')` | 앞쪽 `v{N} 평가 결과`는 유지 권장 |
| E7 | my.js `#review-list` | `총점 4점`(= `총점 N점`) | `toContainText('총점 4점')` | `총점 N점` 형식 유지 |
| E8 | my.js 핀 배지 | `1-1`, `1-2` (평가자라벨-핀번호) | `toHaveText('1-1')` | 형식 **변경 금지** |
| E9 | review.js 핀 삭제 버튼 | `삭제` | `getByRole('button', {name:'삭제'})` 부분 일치 | `삭제`를 포함하면 가능. 같은 `.pin-item` 안에 이름에 `삭제`가 들어간 버튼을 하나만 둔다 |
| E10 | review.js `#pin-count` | `2 / 50` (`N / 50`) | `toContainText('2 / 50')` | `N / 50` 형식 유지. 앞뒤 글자는 가능 |
| E11 | review.js `#target-version` | `v2` 포함 | demo: `textContent().includes('v2')` | `v{N}` 유지 |
| E12 | review.js `#other-btn` | `window.confirm` 대화상자 | demo: `page.once('dialog', d => d.accept())` | 확인창은 유지. 문구는 자유 |
| E13 | upload.js `#terms .chip` | 가릴 단어 텍스트(예: `김하늘`) 포함 | `toContainText`. 칩 안 첫 `span`이 단어(demo가 `.chip > span`을 읽는다) | 칩 구조와 단어 텍스트 유지. 삭제 버튼 문구는 자유 |
| E14 | upload.js `#unmatched .msg` | 이름이 문서에서 찾아지면 `.msg`가 0개 | `toHaveCount(0)` | 일치 없을 때만 `.msg` 생성 유지 |
| E15 | review.js | `#done-area .banner` 보임, 제출 후 `#empty-area` 보임, `#review-area` 숨김 | 가시성만 확인 | 배너·빈 화면 문구는 자유. 배너 클래스와 id는 유지 |

문구는 아니지만 같은 파일에서 쓰는 선택자도 함께 보존해야 한다: `#title #targetRole #file #upload-btn #preview-card #summary #term #term-btn #terms #unmatched #pages #confirm #publish-btn #done-card #pin-list .pin-item textarea #review-form #score(input[name=score]) #submit-btn #resume-list #version-list li[data-no] #new-version-link #pin-empty #review-empty #demo-btn #pages-end .my-pin .my-pinitem .page-wrap .pin #name-candidate button`.
`#summary`는 upload.html(카운트 칩 영역)과 review.html(총평 textarea)에서 id가 같지만 서로 다른 페이지다.

## 3. 히어로 (랜딩) 3안

`h1`은 서비스 이름으로 고정이다. 아래 헤드라인은 `h1` 위의 문제 제기 한 줄(`.problem`)과 `h1` 아래 하위 문구(`.value`) 후보다. 데모 첫 30초에 "문제 2개 + 결과"가 읽혀야 한다.

### 헤드라인(`.problem`) 3안

| 안 | 문구 | 의도 |
|---|---|---|
| A (기본 추천) | 이름 붙은 이력서, 지인 몇 명한테만 보여 주고 피드백은 카톡에 흩어져 있죠? | 문제 1(이름 노출·소수)과 2(흩어짐)를 한 문장에 담는다. 대화체로 잔소리 톤 |
| B | 이력서 평가 받고 싶은데, 이름까지 내놓기는 싫었죠? | 문제 1에 집중. 거부감을 공감으로 시작. 짧아서 영상 자막에 좋다 |
| C | 고칠 때마다 점수가 어떻게 달라졌는지, 어디에 적어 두셨어요? | 문제 2(버전별 비교)에 집중. 결과 화면(추이)으로 바로 이어진다 |

### 하위 문구(`.value`) 3안

| 안 | 문구 | 의도 |
|---|---|---|
| A (기본 추천) | 이름과 연락처, 사진은 검게 가리고 디자인은 그대로. 평가자는 가려진 이미지만 보고, 버전마다 받은 핀과 점수는 한 화면에 모여요. | 핵심 메시지 둘(이름 안 드러남 + 버전별 모음)을 모두 담는다. 저장 범위가 아니라 "평가자가 보는 것"을 약속 |
| B | 이름은 검게 가리고 레이아웃은 그대로. 모르는 사람의 핀 첨삭이 v1에서 v2까지 점수 추이로 이어져요. | 가장 짧다(2문장). 핀·추이 용어 노출 |
| C | 회원가입도, 이름도 필요 없어요. 가려진 이력서에 핀으로 받은 첨삭을 버전별로 모아 비교해요. | "필요 없음" 약속을 앞세운 안심형 |

주의: 하위 문구에 "이름을 자동으로 가려요"를 쓰지 않는다(이름은 사용자가 확인하고 가린다). "저장되는 것은 가린 이미지뿐"도 쓰지 않는다(3절 요약 3번). 쓰려면 "평가자에게 보이는 것은 가린 이미지뿐이에요"로 쓴다.

### 안심 문구(`.assure`) 짧은 형태 3안

1. 회원가입 없음 · 평가자에게는 가린 이미지만 · 원본 PDF는 게시하면 바로 삭제
2. 회원가입 없음 · 이름은 내가 확인하고 가려요 · 원본 PDF는 게시하는 순간 지워져요
3. 이름도 가입도 필요 없어요 · 보이는 건 가린 이미지뿐 · 원본 PDF는 올린 뒤 24시간 안에 사라져요

(1안은 "게시하면 바로"가 초안 24시간 예외를 숨긴다. 정확함을 우선하면 2안을 쓴다. 한 줄에 다 못 담으면 24시간 예외는 업로드 화면에서 안내하므로 괜찮다.)

## 6. 말투·길이 점검 결과

해요체로 고칠 합니다체 문구(요약):

| 파일 | 현재 | 제안 |
|---|---|---|
| review.html | 아직 핀이 없습니다. 핀 없이 총평과 총점만 제출해도 됩니다. | 아직 핀이 없어요. 핀 없이 총평과 총점만 보내도 돼요. |
| my.html | 핀 코멘트가 없습니다. | 핀 코멘트가 없어요. |
| api.js | 네트워크 오류가 발생했습니다. 잠시 후 다시 시도해 주세요. | 서버에 연결하지 못했어요. 잠시 뒤 다시 시도해 주세요. |
| 서버 메시지 전반 | …합니다 / …하세요 | 7절 |

길이: 가장 긴 문구는 랜딩 안심 문구와 게시 완료 안심 문구다. 모두 한 줄(모바일 375px에서 두 줄)에 들어가도록 `·` 구분 3토막 이내로 유지한다. 새로 제안한 문구 중 가장 긴 것은 ERRORS.NO_TEXT_LAYER(약 55자)이고 오류 영역은 줄바꿈 허용이라 문제없다. E2E는 375px에서 가로 넘침이 없어야 하므로(`noOverflow`), 긴 문구를 추가할 때는 `.msg`/`.muted`에 줄바꿈이 허용되는지 확인한다.

조사 처리(E4): `v${n}을` 대신 숫자의 받침으로 고른다. 받침이 있는 숫자는 1, 3, 6, 7, 8, 10, 11, 13, ... (일·삼·육·칠·팔·십). 그 외 2, 4, 5, 9는 `를`. 정규식 `/v{N}.{1,2} 게시했어요/`는 두 경우 모두 통과한다. 10 이상은 `v10을`처럼 한 글자 조사이므로 E4를 만족한다.

## 7. 서버 오류 메시지 (Java 쪽, 화면에 그대로 노출됨)

## 8. 반영 우선순위

1. (정확성) 랜딩 1단계 "이름 자동" 오류, 안심 문구의 24시간 예외. 데모 전에 반드시.
2. (정확성) `v2을` 조사.
3. (핵심 메시지) 히어로 A안, 미리보기 안내 문구, 게시 완료 안심 문구, 추이 요약 단위(`점`).
4. (일관성) 합니다체 문구 4곳과 서버 메시지의 해요체.
5. (용어) 마스킹 → 가림 5곳(upload.html 제목, alt 3곳, 경고).
6. (선택) 감사 한마디, 제출 전 안내.

반영 후 확인: `e2e/run.sh e2e`가 통과해야 한다(1절 E1~E15). 문구만 바꾸는 작업이라 `./gradlew test bootJar`는 영향이 없을 것으로 보이나 서버 메시지를 건드리면 반드시 돌린다.
