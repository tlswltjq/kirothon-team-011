# 요구사항: 익명 이력서 평가와 버전별 평가 이력

## 소개
이력서를 고쳐 가며 지원하는 취업·이직 준비자는 평가를 많이 받을수록 좋지만, 채용 플랫폼과 연계된 평가 서비스는 이름과 이력서 원본을 공개해야 해서 거부감이 든다. 지인에게 부탁하면 평가자가 몇 명뿐이다. 개인정보를 지운 텍스트만 보여 주면 이력서 디자인(가시성·시인성)은 평가받지 못한다. 받은 피드백은 메신저와 메일에 흩어져 "v1보다 v2가 나아졌는가"를 확인할 수 없다.

이 기능은 PDF 이력서를 페이지 이미지로 렌더링하면서 이메일·전화번호·URL·지정 단어·사진을 검은 박스로 가리고, 그 이미지만 익명 사용자들에게 무작위로 보여 준다. 평가자는 이미지 위의 위치를 눌러 첨삭 핀과 코멘트를 남기고 총평과 총점을 낸다. 주인은 버전마다 모든 평가자의 핀을 페이지 위에 겹쳐 보고, 버전 간 평균 총점 추이와 바뀐 문장을 비교한다.

## 용어
- **익명 사용자**: 회원가입 없이 닉네임과 브라우저 토큰으로 식별되는 사용자.
- **토큰**: 첫 방문 때 서버가 발급하는 무작위 문자열. 브라우저가 보관하고 요청 헤더 `X-Anon-Token`으로 보낸다.
- **주인**: 이력서를 올린 익명 사용자.
- **평가자**: 남의 이력서를 평가하는 익명 사용자.
- **이력서**: 주인이 관리하는 한 묶음. 제목(주인만 봄)과 지원 직무(평가자도 봄)를 가진다.
- **버전**: 이력서에 올린 PDF 하나에서 만든 v1, v2, ... 단위. 상태는 초안 또는 게시됨이다.
- **원본 PDF**: 주인이 올린 PDF 바이트. 초안 동안만 미리보기 재생성용으로 임시 보관하고 게시하면 지운다. 누구에게도 응답하지 않는다.
- **추출 텍스트**: PDF에서 뽑은 줄 텍스트를 페이지 순서대로 이어 붙인 것. 주인만 볼 수 있고 버전 비교에 쓴다.
- **줄 텍스트**: 같은 줄에 놓인 글자를 왼쪽부터 이어 붙인 문자열. 각 글자는 페이지와 좌표 영역에 대응한다. 자동 마스킹은 줄 텍스트에서 찾는다.
- **가릴 단어**: 주인이 직접 지정하는 이름·회사·학교 등의 단어.
- **마스킹 영역**: 페이지 이미지에서 검게 칠할 사각형. 유형은 이메일·전화·링크·가릴 단어·이미지·수동(2순위)이다.
- **마스킹 이미지**: 페이지를 PNG로 렌더링한 뒤 마스킹 영역을 불투명 검은색으로 칠한 이미지. 평가자에게 보이는 유일한 이력서 내용이다.
- **미리보기**: 초안의 마스킹 이미지와 유형별 가린 개수, 일치 없는 단어, 경고를 묶은 것.
- **미리보기 해시(previewHash)**: 서버가 미리보기 PNG 바이트로 계산한 SHA-256. 주인이 확인한 이미지와 게시할 이미지가 같은지 확인하는 데 쓴다.
- **후보**: 무작위 평가 대상이 될 수 있는 버전.
- **핀(첨삭 핀)**: 평가자가 마스킹 이미지의 한 지점에 남긴 코멘트. 페이지 번호와 정규화 좌표, 코멘트(1~500자)를 가진다.
- **정규화 좌표**: 핀 위치를 페이지 이미지 너비·높이에 대한 비율(x, y 각각 0 이상 1 이하)로 나타낸 값. 왼쪽 위가 (0, 0)이다. 화면 크기와 관계없이 같은 위치를 가리킨다.
- **평가**: 한 평가자가 한 버전에 한 번 제출하는 핀 목록(0개 이상), 총평(필수, 20자 이상), 총점(1~5 정수, 필수)의 묶음.
- **평가자 라벨**: 주인 화면에서 평가자를 구분하는 "평가자 1, 2, ..." 표시. 버전 안에서 제출 순서로 매긴다.
- **데모 프로필**: 샘플 데이터 기능을 켜는 Spring 프로필 `demo`.

## 요구사항 (MVP)

> 2026-11-14 우선순위: MVP 핵심은 마스킹과 익명 평가다. 9.3·9.4·9.6(추이·필터), 요구사항 10(변경 비교), 요구사항 14(복구 코드)는 확장 작업 12·16에서 구현한다.

### 요구사항 1: 익명으로 시작하기
**사용자 이야기:** 취업 준비자로서, 이름과 연락처를 남기지 않고 서비스를 쓰기 위해 닉네임만으로 시작하기를 원한다.

#### 인수 조건
- **1.1** WHEN 토큰이 없는 브라우저가 첫 화면을 열면 THE SYSTEM SHALL 닉네임 입력 화면을 보여 준다.
- **1.2** WHEN 사용자가 앞뒤 공백을 뺀 2~20자 닉네임을 제출하면 THE SYSTEM SHALL 256비트 무작위 토큰을 발급해 응답하고, 서버에는 토큰의 SHA-256 해시만 저장한다.
- **1.3** WHEN 토큰을 발급하면 THE SYSTEM SHALL 브라우저 저장소를 지우거나 다른 브라우저를 쓰면 내 이력서에 다시 접근할 수 없다는 안내를 보여 준다.
- **1.4** IF 닉네임이 비었거나 2자 미만 또는 20자 초과이면 THEN THE SYSTEM SHALL 400 `VALIDATION_FAILED`로 거부하고 토큰을 발급하지 않는다.
- **1.5** IF 인증이 필요한 API 요청에 토큰이 없거나 서버가 모르는 토큰이면 THEN THE SYSTEM SHALL 401 `UNAUTHENTICATED`로 거부한다.
- **1.6** WHEN 평가 대상이나 평가 목록을 보여 줄 때 THE SYSTEM SHALL 주인 닉네임을 평가자에게, 평가자 닉네임을 주인에게 보여 주지 않는다. 주인 화면의 평가자는 평가자 라벨로 표시한다.

### 요구사항 2: PDF 업로드와 좌표 포함 텍스트 추출
**사용자 이야기:** 주인으로서, 이미 가진 PDF 이력서를 다시 만들지 않고 디자인까지 평가받기 위해 PDF를 그대로 올리기를 원한다.

#### 인수 조건
- **2.1** WHEN 주인이 제목(1~60자), 지원 직무(1~40자), PDF 파일을 올리면 THE SYSTEM SHALL 글자별 좌표를 포함해 텍스트를 추출하고, 이력서와 v1 초안을 만들고, 자동 마스킹 미리보기(요구사항 3)를 응답한다.
- **2.2** WHEN 텍스트를 추출하면 THE SYSTEM SHALL 페이지마다 줄 텍스트를 만들고, 줄 텍스트의 각 글자를 페이지와 좌표 영역에 대응시키고, 줄 텍스트를 페이지 순서대로 이어 붙여 추출 텍스트로 저장한다.
- **2.3** IF 파일의 첫 5바이트가 `%PDF-`가 아니면 THEN THE SYSTEM SHALL 확장자나 Content-Type과 관계없이 400 `NOT_PDF`로 거부한다.
- **2.4** IF 파일이 5MB를 넘으면 THEN THE SYSTEM SHALL 413 `FILE_TOO_LARGE`로 거부한다.
- **2.5** IF PDF가 10쪽을 넘으면 THEN THE SYSTEM SHALL 422 `TOO_MANY_PAGES`로 거부한다.
- **2.6** IF PDF가 암호화되어 있으면 THEN THE SYSTEM SHALL 422 `ENCRYPTED_PDF`로 거부하고 암호를 해제한 PDF를 올리라고 안내한다.
- **2.7** IF 추출한 텍스트가 공백을 빼고 100자 미만이면 THEN THE SYSTEM SHALL 422 `NO_TEXT_LAYER`로 거부하고, 스캔본은 자동 마스킹을 할 수 없어 지원하지 않으며 텍스트가 선택되는 PDF로 다시 저장하라고 안내한다. (2순위 13.5가 생기면 이 조건은 13.5로 바뀐다.)
- **2.8** IF PDF를 해석할 수 없으면 THEN THE SYSTEM SHALL 422 `PDF_PARSE_FAILED`로 거부한다.
- **2.9** IF 추출과 렌더링이 20초 안에 끝나지 않거나 PDF에 포함된 이미지 하나가 2,500만 픽셀을 넘으면 THEN THE SYSTEM SHALL 처리를 중단하고 422 `PDF_TOO_COMPLEX`로 거부한다.
- **2.10** IF 페이지 회전값(`/Rotate`)이 0이 아닌 페이지가 있으면 THEN THE SYSTEM SHALL 422 `UNSUPPORTED_PAGE_ROTATION`으로 거부하고 회전 없이 다시 저장하라고 안내한다.
- **2.11** IF 업로드가 2.3~2.10 중 하나로 거부되면 THEN THE SYSTEM SHALL 이력서, 버전, 원본 PDF를 저장하지 않는다.
- **2.12** IF 지원 직무에 이메일·전화번호·URL 패턴이 있으면 THEN THE SYSTEM SHALL 400 `VALIDATION_FAILED`로 거부한다. 지원 직무는 평가자에게 글자 그대로 보이기 때문이다.
- **2.13** WHEN 추출한 글자 중 유니코드로 바꿀 수 없는 글자(매핑 없음, U+FFFD, 사설 영역 문자)가 있으면 THE SYSTEM SHALL 해당 페이지 번호와 함께 "일부 글자를 읽지 못해 자동 마스킹이 빠질 수 있습니다. 미리보기를 꼼꼼히 확인하세요" 경고를 미리보기에 넣는다. (ToUnicode 정보가 없는 글꼴의 알려진 한계)

### 요구사항 3: 자동·지정 마스킹 미리보기
**사용자 이야기:** 주인으로서, 신상이 드러나지 않는다는 확신을 갖고 공개하기 위해 평가자가 볼 페이지 이미지를 게시 전에 확인하고 가릴 단어를 추가하기를 원한다.

#### 인수 조건
- **3.1** WHEN 초안이 만들어지면 THE SYSTEM SHALL 줄 텍스트에서 이메일, 전화번호(한국 휴대폰·지역번호·`+82` 형식, 구분자 `-`·`.`·공백 포함), URL을 찾고 일치한 글자들의 좌표 영역을 마스킹 영역으로 정한다.
- **3.2** WHEN 초안이 만들어지면 THE SYSTEM SHALL 페이지에 그려진 모든 이미지(증명사진·로고 등)의 표시 영역을 마스킹 영역에 넣는다.
- **3.3** WHEN 주인이 초안에 가릴 단어 목록을 제출하면 THE SYSTEM SHALL 줄 텍스트에서 대소문자를 무시하고 글자 사이 공백을 허용해 일치하는 부분을 찾아 마스킹 영역에 넣고 새 미리보기를 응답한다.
- **3.4** WHEN 미리보기를 만들 때 THE SYSTEM SHALL 각 페이지를 150DPI PNG로 렌더링한 뒤 모든 마스킹 영역을 불투명 검은색(RGB 0,0,0) 사각형으로 칠한다. PDF 위에 박스를 덮어 PDF로 저장하는 방식은 쓰지 않는다.
- **3.5** WHEN 페이지를 렌더링할 때 THE SYSTEM SHALL 주석(annotation)과 양식 필드 모양을 그리지 않는다. 텍스트 추출로 찾을 수 없는 내용이 이미지에 나타나지 않게 하기 위해서다.
- **3.6** WHEN 미리보기를 응답할 때 THE SYSTEM SHALL 페이지 수, 유형별 가린 개수, previewHash, 2.13 경고를 응답하고, 화면은 마스킹 이미지를 페이지 순서대로 보여 준다.
- **3.7** WHEN 지정한 가릴 단어가 줄 텍스트에서 한 번도 일치하지 않으면 THE SYSTEM SHALL 미리보기에 그 단어를 "일치 없음"으로 표시한다(오타 확인용).
- **3.8** WHEN 미리보기를 만들 때 추출 텍스트의 첫 번째 비어 있지 않은 줄이 마스킹 영역에 덮이지 않았으면 THE SYSTEM SHALL 그 줄(최대 30자)을 이름 후보로 제안하고, 주인이 누르면 가릴 단어에 추가한다.
- **3.9** IF 가릴 단어가 2자 미만 또는 30자 초과이거나 50개를 넘으면 THEN THE SYSTEM SHALL 400 `VALIDATION_FAILED`로 거부하고 이전 미리보기를 유지한다.

### 요구사항 4: 미리보기 확인 후 게시
**사용자 이야기:** 주인으로서, 가림이 빠진 이미지가 실수로 공개되지 않게 하기 위해 내가 확인한 미리보기 그대로만 게시되기를 원한다.

#### 인수 조건
- **4.1** WHEN 주인이 "모든 페이지를 확인했습니다" 확인값과 최신 previewHash로 게시를 요청하고 4.4 검증을 통과하면 THE SYSTEM SHALL 주인이 확인한 미리보기 PNG를 게시 이미지로 고정하고 버전을 게시됨으로 바꾼다.
- **4.2** IF 게시 요청의 previewHash가 없거나 그 초안의 최신 미리보기 해시와 다르면 THEN THE SYSTEM SHALL 409 `PREVIEW_OUTDATED`로 거부하고 초안을 유지한다. 미리보기를 받지 않은 클라이언트는 게시할 수 없다.
- **4.3** IF 게시 요청에 확인값이 참으로 들어 있지 않으면 THEN THE SYSTEM SHALL 400 `VALIDATION_FAILED`로 거부한다.
- **4.4** WHEN 게시를 검증할 때 THE SYSTEM SHALL 보관 중인 원본 PDF와 저장된 가릴 단어로 마스킹 영역을 다시 계산해 저장된 영역이 그것을 모두 덮는지 확인하고, 게시할 PNG에서 모든 마스킹 영역의 픽셀이 RGB(0,0,0)인지 확인한다.
- **4.5** IF 4.4 검증이 실패하면 THEN THE SYSTEM SHALL 422 `MASKING_INCOMPLETE`로 거부하고 실패한 페이지와 영역 유형을 주인에게 응답하며 초안을 유지한다.
- **4.6** WHEN 버전이 게시되면 THE SYSTEM SHALL 같은 트랜잭션에서 원본 PDF를 지운다.
- **4.7** WHILE 버전이 초안이면 THE SYSTEM SHALL 원본 PDF를 업로드 후 최대 24시간만 보관하고, 지나면 지운다.
- **4.8** IF 원본 PDF가 지워진 초안에 가릴 단어 변경이나 게시를 요청하면 THEN THE SYSTEM SHALL 410 `DRAFT_SOURCE_EXPIRED`로 거부하고 같은 PDF를 다시 올리라고 안내한다.
- **4.9** IF 이미 게시된 버전에 게시나 가릴 단어 변경을 요청하면 THEN THE SYSTEM SHALL 409 `ALREADY_PUBLISHED`로 거부한다. 게시 이미지는 바뀌지 않는다.

### 요구사항 5: 이력서 버전 관리
**사용자 이야기:** 주인으로서, 고친 이력서가 나아졌는지 확인하기 위해 같은 이력서에 새 PDF를 올려 버전별로 평가받기를 원한다.

#### 인수 조건
- **5.1** WHEN 주인이 자기 이력서에 새 PDF를 올리면 THE SYSTEM SHALL 마지막 버전 번호에 1을 더한 초안을 만들고 2.1과 같은 추출·자동 마스킹 미리보기를 응답한다.
- **5.2** WHEN 새 버전 초안을 만들면 THE SYSTEM SHALL 직전 버전의 가릴 단어를 미리 적용한 미리보기를 응답한다.
- **5.3** WHEN 게시 전 초안이 있는 이력서에 새 PDF를 올리면 THE SYSTEM SHALL 새 버전을 추가하지 않고 그 초안의 원본 PDF, 추출 텍스트, 미리보기를 새 PDF 내용으로 교체하고 가릴 단어는 유지한다.
- **5.4** IF 새 버전 PDF가 2.3~2.10 중 하나로 거부되면 THEN THE SYSTEM SHALL 같은 오류 코드로 응답하고 기존 초안과 버전을 바꾸지 않는다.
- **5.5** WHEN 새 버전이 게시되면 THE SYSTEM SHALL 이전 버전의 게시 이미지, 추출 텍스트, 평가와 핀, 통계를 그대로 보존한다.

### 요구사항 6: 무작위 평가 대상 받기
**사용자 이야기:** 평가자로서, 고르는 부담 없이 바로 평가하기 위해 시스템이 무작위로 골라 준 익명 이력서를 받기를 원한다.

#### 인수 조건
- **6.1** WHEN 사용자가 평가할 이력서를 요청하면 THE SYSTEM SHALL 후보 중 하나를 균등 확률로 골라 버전 id, 버전 번호, 지원 직무, 페이지 수만 응답한다.
- **6.2** WHEN 평가자가 받은 버전을 열면 THE SYSTEM SHALL 게시된 마스킹 이미지를 페이지 순서대로 화면 폭에 맞춰 보여 준다.
- **6.3** WHEN 후보를 정할 때 THE SYSTEM SHALL 게시됨 상태인 모든 버전을 포함하고, 요청자의 이력서에 속한 버전과 요청자가 이미 평가한 버전만 뺀다. 같은 이력서의 이전 게시 버전도 후보에 남는다.
- **6.4** WHEN 후보를 정할 때 THE SYSTEM SHALL 크레딧, 평가 횟수, 직무 일치 여부를 조건이나 가중치로 쓰지 않는다. 평가를 한 번도 하지 않은 사용자의 이력서도 후보가 된다.
- **6.5** WHEN 평가자가 "다른 이력서" 요청에 방금 받은 버전 id를 함께 보내고 후보가 2개 이상이면 THE SYSTEM SHALL 그 버전을 빼고 다시 무작위로 고른다.
- **6.6** IF 후보가 없으면 THEN THE SYSTEM SHALL 404 `NO_REVIEWABLE_RESUME`로 응답하고 화면에 "지금은 평가할 이력서가 없습니다" 안내를 보여 준다.

### 요구사항 7: 이미지 위 첨삭 핀 작성
**사용자 이야기:** 평가자로서, 디자인과 문장을 구체적으로 지적하기 위해 페이지 이미지의 해당 위치에 바로 코멘트를 남기기를 원한다.

#### 인수 조건
- **7.1** WHEN 평가자가 마스킹 이미지의 한 지점을 누르면 THE SYSTEM SHALL 그 위치에 번호가 붙은 핀을 놓고 코멘트 입력란을 연다.
- **7.2** WHEN 핀 위치를 기록할 때 THE SYSTEM SHALL 페이지 번호(1부터)와 표시된 이미지 너비·높이에 대한 정규화 좌표 x, y(0 이상 1 이하)로 기록한다.
- **7.3** WHEN 핀을 화면에 그릴 때 THE SYSTEM SHALL 정규화 좌표에 현재 표시 크기를 곱한 위치에 그린다. 창 크기나 화면 폭이 달라도 핀은 이미지의 같은 지점에 놓인다.
- **7.4** WHILE 평가를 제출하기 전이면 THE SYSTEM SHALL 평가자가 자기 핀의 코멘트를 고치거나 핀을 지울 수 있게 하고, 핀은 브라우저에만 두며 서버에 저장하지 않는다.
- **7.5** IF 제출된 핀의 페이지 번호가 1~페이지 수 범위 밖이거나, x 또는 y가 숫자가 아니거나 0~1 범위 밖이면 THEN THE SYSTEM SHALL 400 `VALIDATION_FAILED`로 거부하고 해당 핀 순번을 필드 오류로 응답한다.
- **7.6** IF 핀 코멘트가 앞뒤 공백을 빼고 1자 미만 또는 500자 초과이거나, 한 평가의 핀이 50개를 넘으면 THEN THE SYSTEM SHALL 400 `VALIDATION_FAILED`로 거부한다.

### 요구사항 8: 평가 제출
**사용자 이야기:** 평가자로서, 짧은 시간에 쓸모 있는 피드백을 남기기 위해 위치별 첨삭과 함께 총평과 총점을 한 번에 제출하기를 원한다.

#### 인수 조건
- **8.1** WHEN 평가자가 핀 0개 이상, 앞뒤 공백을 뺀 20~1000자 총평, 1~5 정수 총점을 제출하면 THE SYSTEM SHALL 평가와 모든 핀을 한 트랜잭션으로 저장하고 201로 응답하며 다음 이력서 평가로 이어지는 버튼을 보여 준다.
- **8.2** IF 총점이 빠졌거나 1~5 정수가 아니면 THEN THE SYSTEM SHALL 400 `VALIDATION_FAILED`로 거부하고 필드별 오류를 응답한다.
- **8.3** IF 총평이 빠졌거나 앞뒤 공백을 빼고 20자 미만이거나 1000자를 넘으면 THEN THE SYSTEM SHALL 400 `VALIDATION_FAILED`로 거부한다.
- **8.4** IF 제출 내용이 7.5, 7.6, 8.2, 8.3 중 하나라도 어기거나 저장 중 오류가 나면 THEN THE SYSTEM SHALL 평가와 핀을 하나도 저장하지 않는다.
- **8.5** IF 같은 사용자가 같은 버전에 다시 평가를 제출하면 THEN THE SYSTEM SHALL 동시 요청을 포함해 409 `DUPLICATE_REVIEW`로 거부하고 기존 평가와 핀을 유지한다.
- **8.6** THE SYSTEM SHALL 제출된 평가와 핀을 수정하거나 지우는 API를 제공하지 않는다.
- **8.7** IF 평가자가 자기 이력서의 버전에 평가를 제출하면 THEN THE SYSTEM SHALL 403 `SELF_REVIEW`로 거부한다.
- **8.8** IF 평가 대상 버전이 없거나 초안이면 THEN THE SYSTEM SHALL 404 `NOT_FOUND`로 거부한다.
- **8.9** WHEN 평가 작성 중 주인이 새 버전을 게시한 뒤 이전 버전에 평가가 제출되면 THE SYSTEM SHALL 그 평가를 이전 버전의 평가로 저장한다.

### 요구사항 9: 버전별 평가 이력
**사용자 이야기:** 주인으로서, 어떤 수정이 효과가 있었는지 알기 위해 버전별 첨삭과 점수 추이를 한 화면에서 보기를 원한다.

#### 인수 조건
- **9.1** WHEN 주인이 내 이력서 목록을 열면 THE SYSTEM SHALL 요청자가 주인인 이력서만 제목, 최신 버전 번호, 전체 평가 수와 함께 보여 준다.
- **9.2** WHEN 주인이 이력서를 열면 THE SYSTEM SHALL 버전마다 상태, 게시 시각, 평가 수, 평균 총점(소수 둘째 자리 반올림)을 보여 준다.
- **9.3** WHEN 게시된 버전이 2개 이상이면 THE SYSTEM SHALL 버전 순서대로 평균 총점을 잇는 추이 차트(외부 라이브러리 없이 그린 SVG)와 직전 게시 버전 대비 증감을 보여 준다.
- **9.4** IF 버전에 평가가 0개이면 THEN THE SYSTEM SHALL 평균 대신 "평가 없음"을 보여 주고, 차트에서 그 버전의 점을 그리지 않으며, 그 버전과 이웃 버전 사이의 증감을 표시하지 않는다.
- **9.5** WHEN 주인이 버전을 고르면 THE SYSTEM SHALL 그 버전의 게시 이미지 위에 모든 평가자의 핀을 겹쳐 표시하고, 핀마다 평가자별 색과 "평가자 라벨-핀 번호"(예: 2-3)를 붙인다.
- **9.6** WHEN 주인이 평가자 필터에서 평가자를 고르면 THE SYSTEM SHALL 고른 평가자의 핀만 이미지 위에 표시하고, "전체"를 고르면 모든 핀을 다시 표시한다.
- **9.7** WHEN 주인이 버전을 고르면 THE SYSTEM SHALL 이미지 옆에 핀 코멘트 목록(평가자 라벨, 페이지, 핀 번호, 코멘트)과 평가별 총점·총평·작성 시각 목록을 최신순으로 보여 주고, 목록의 핀을 누르면 이미지 위의 해당 핀을 강조한다.
- **9.8** THE SYSTEM SHALL 핀을 그 핀이 남겨진 버전의 이미지에만 표시하고 다른 버전으로 이월하지 않는다. 버전마다 레이아웃이 다를 수 있기 때문이다.

### 요구사항 10: 버전 간 변경 비교
**사용자 이야기:** 주인으로서, 점수 변화가 어떤 문장 변경에서 왔는지 보기 위해 이전 버전과 현재 버전의 텍스트 차이를 보기를 원한다.

#### 인수 조건
- **10.1** WHEN 주인이 v(n) (n ≥ 2)의 변경 비교를 요청하면 THE SYSTEM SHALL v(n-1)과 v(n)의 추출 텍스트를 줄 단위로 비교해 추가·삭제·유지 줄을 순서대로 응답하고, 화면은 색으로 구분해 보여 준다.
- **10.2** WHEN 변경 비교를 응답할 때 THE SYSTEM SHALL 추가된 줄 수와 삭제된 줄 수 요약을 함께 응답한다.
- **10.3** WHEN 변경 비교를 만들 때 THE SYSTEM SHALL 주인 전용 추출 텍스트끼리 비교하고 그 결과를 주인에게만 응답한다. 디자인만 바뀐 경우 차이가 없을 수 있다는 안내를 함께 보여 준다.
- **10.4** IF v1의 변경 비교를 요청하면 THEN THE SYSTEM SHALL 409 `NO_PREVIOUS_VERSION`으로 응답한다.

### 요구사항 11: 원본·추출 텍스트와 개인정보 접근 경계
**사용자 이야기:** 주인으로서, 안심하고 올리기 위해 내 원본과 신상 정보가 나 말고 누구에게도 보이지 않기를 원한다.

#### 인수 조건
- **11.1** IF 주인이 아닌 사용자가 남의 이력서나 버전의 추출 텍스트, 미리보기와 미리보기 이미지, 가릴 단어, 마스킹 영역, 평가와 핀 목록, 통계, 변경 비교를 조회하거나 업로드·마스킹·게시를 요청하면 THEN THE SYSTEM SHALL 404 `NOT_FOUND`로 거부하고 응답에 그 이력서의 데이터를 넣지 않는다. 존재 여부도 알리지 않기 위해 403 대신 404를 쓴다.
- **11.2** WHEN 평가자에게 평가 대상이나 페이지 이미지를 응답할 때 THE SYSTEM SHALL 추출 텍스트, 원본 PDF, 이력서 제목, 이력서 id, 주인 닉네임, 가릴 단어, 마스킹 영역 좌표, 다른 평가자의 평가·핀을 응답에 넣지 않는다.
- **11.3** WHEN 어떤 API든 응답할 때 THE SYSTEM SHALL 다른 사용자의 토큰, 토큰 해시, 사용자 id를 응답에 넣지 않는다. 주인에게 보이는 평가에는 평가자 라벨만 들어간다.
- **11.4** THE SYSTEM SHALL 주인을 포함한 누구에게도 원본 PDF 바이트를 응답하지 않는다. `application/pdf` 응답을 만드는 경로가 없다.
- **11.5** IF 평가자용 페이지 이미지 경로로 초안 버전이나 없는 페이지를 요청하면 THEN THE SYSTEM SHALL 404 `NOT_FOUND`로 거부한다. 이 경로는 게시된 마스킹 이미지만 응답한다.
- **11.6** WHEN 서버가 로그를 남길 때 THE SYSTEM SHALL 토큰, 추출 텍스트, 가릴 단어, PDF 바이트, 핀 코멘트, 총평을 로그에 쓰지 않는다.
- **11.7** WHEN 화면이 추출 텍스트, 핀 코멘트, 총평, 닉네임, 지원 직무를 표시할 때 THE SYSTEM SHALL 내용을 HTML로 해석하지 않고 글자 그대로 표시한다.
- **11.8** WHEN 서버가 시작되면 THE SYSTEM SHALL `127.0.0.1`에만 바인딩하고 actuator는 `/actuator/health`만 노출한다.

### 요구사항 12: 데모용 샘플 데이터
**사용자 이야기:** 발표자로서, 3분 데모에서 평가가 쌓인 화면을 바로 보여 주기 위해 샘플 이력서와 평가를 명시적으로 넣기를 원한다.

#### 인수 조건
- **12.1** WHEN 앱이 시작되면 THE SYSTEM SHALL 프로필과 관계없이 샘플 데이터를 자동으로 넣지 않는다.
- **12.2** WHILE 데모 프로필이 꺼져 있으면 THE SYSTEM SHALL 샘플 데이터 버튼을 숨기고 샘플 데이터 API를 404 `NOT_FOUND`로 응답한다.
- **12.3** WHEN 데모 프로필이 켜진 상태에서 사용자가 샘플 데이터 버튼을 누르면 THE SYSTEM SHALL 샘플 사용자 3명의 게시된 이력서와, 요청자 소유의 샘플 이력서 v1·v2(v2는 디자인과 문장을 고친 판)를 실제 업로드·마스킹·게시 경로로 만들고, 각 버전에 핀이 포함된 샘플 평가를 넣는다. v2 평균 총점은 v1보다 높다.
- **12.4** WHEN 샘플 데이터를 보여 줄 때 THE SYSTEM SHALL 이력서와 평가에 "샘플" 표시를 붙인다. 샘플 PDF는 실존하지 않는 인물·회사·연락처와 가상 사진 이미지로 만든다.
- **12.5** IF 같은 사용자가 샘플 데이터를 다시 요청하면 THEN THE SYSTEM SHALL 409 `DEMO_ALREADY_SEEDED`로 응답하고 데이터를 중복으로 만들지 않는다.

## 요구사항 (2순위, MVP 이후)

### 요구사항 13: 수동 박스 마스킹
**사용자 이야기:** 주인으로서, 자동 마스킹이 놓친 부분(글자가 깨진 글꼴, 글자를 도형으로 바꾼 로고, 스캔본)을 가리기 위해 페이지 이미지 위에 직접 박스를 그리기를 원한다.

#### 인수 조건
- **13.1** WHEN 주인이 초안 미리보기 이미지 위에서 드래그로 사각형을 그리고 저장하면 THE SYSTEM SHALL 그 사각형을 수동 마스킹 영역으로 저장하고 새 미리보기와 previewHash를 응답한다.
- **13.2** WHEN 주인이 수동 마스킹 영역을 지우면 THE SYSTEM SHALL 남은 영역으로 새 미리보기와 previewHash를 응답한다.
- **13.3** IF 수동 박스가 페이지 밖으로 나가거나, 한 변이 4픽셀 미만이거나, 페이지당 50개를 넘으면 THEN THE SYSTEM SHALL 400 `VALIDATION_FAILED`로 거부하고 이전 미리보기를 유지한다.
- **13.4** WHEN 가릴 단어를 바꿔 미리보기를 다시 만들 때 THE SYSTEM SHALL 저장된 수동 마스킹 영역을 유지한다.
- **13.5** WHEN 수동 마스킹이 켜진 상태에서 텍스트 레이어가 없는 PDF가 올라오면 THE SYSTEM SHALL 2.7 대신 초안을 만들고 "자동 마스킹을 할 수 없으니 직접 가리세요" 경고를 미리보기에 넣는다. 추출 텍스트가 없는 버전의 변경 비교는 "텍스트 없음"으로 표시한다.
- **13.6** WHEN 게시를 검증할 때 THE SYSTEM SHALL 수동 마스킹 영역도 4.4의 픽셀 검사에 포함한다.

## 요구사항 (확장 1순위, 2026-11-14 확정 기능)

### 요구사항 14: 복구 코드로 다른 브라우저에서 이어 쓰기
**사용자 이야기:** 주인으로서, 브라우저 저장소를 잃어도 버전 이력을 계속 쓰기 위해 복구 코드로 같은 익명 계정을 이어 쓰기를 원한다.

#### 인수 조건
- **14.1** WHEN 토큰을 처음 발급하면 THE SYSTEM SHALL 복구 코드를 한 번만 보여 주고 서버에는 해시만 저장한다.
- **14.2** WHEN 다른 브라우저에서 올바른 복구 코드를 입력하면 THE SYSTEM SHALL 같은 사용자에게 새 토큰을 발급하고 이전 토큰을 무효로 한다.
- **14.3** IF 복구 코드가 틀리면 THEN THE SYSTEM SHALL 401 `INVALID_RECOVERY_CODE`로 거부하고, 같은 브라우저 세션에서 연속 5회 실패하면 10분 동안 시도를 막는다.
