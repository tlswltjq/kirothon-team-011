# 제품
- 주제: "내 일상에 바로 적용할 수 있는 서비스" → **익명 이력서 평가와 버전별 평가 이력** (spec: `.kiro/specs/resume-review/`)
- 대상 사용자와 문제(심사 20점): 이력서를 고쳐 가며 지원하는 취업·이직 준비자.
  - 문제 1: 채용 플랫폼과 연계된 평가 서비스는 이름과 이력서 원문을 공개해야 해서 거부감이 든다. 지인에게 부탁하면 평가자가 몇 명뿐이다. 개인정보를 지우려고 텍스트만 복사해 보여 주면 이력서 디자인(가시성·시인성)은 평가받지 못한다.
  - 문제 2: 이력서 평가는 많이 받을수록 좋고 버전마다 평가가 달라지는데, 버전별 평가를 모아 두고 비교할 곳이 없다. 피드백은 메신저와 메일에 흩어진다.
- 사용자 가치(심사 15점): 전: 이름이 드러난 원본을 소수에게 보여 주고, 받은 피드백은 흩어져 버전끼리 비교할 수 없다. 후: 레이아웃은 그대로 두고 이름·연락처·사진만 검게 가린 페이지 이미지로 모르는 다수에게 평가받는다. 평가자는 이미지의 해당 위치에 첨삭 핀을 남기고, 주인은 버전마다 모든 핀을 페이지 위에 겹쳐 보며 v1→v2 평균 총점 추이와 바뀐 문장을 한 화면에서 본다.
- 핵심 흐름 1개: PDF 업로드 → 자동·지정 마스킹 페이지 이미지 미리보기 → 게시 → 다른 사용자가 무작위로 받아 마스킹 이미지 위에 핀 첨삭 + 총평·총점 제출 → 내 이력서 화면에서 버전별 핀 오버레이·평균 총점 추이·변경 비교
- 완료 조건:
  - 두 브라우저(주인, 평가자)로 위 흐름을 끝까지 조작할 수 있다. Playwright E2E 1개가 이 흐름을 통과한다.
  - 실패 경로가 이유와 함께 거부된다: PDF가 아닌 파일, 5MB 초과, 10쪽 초과, 암호화 PDF, 텍스트 없는(스캔본) PDF, 미리보기 없이 또는 오래된 미리보기로 게시, 중복 평가, 평가할 이력서 없음, 남의 원문·미리보기 접근, 범위 밖 핀 좌표(0~1 밖, 없는 페이지).
  - 마스킹 검증 테스트가 통과한다: 렌더링한 PNG에서 마스킹 영역 픽셀이 모두 검은색이고, 평가자 API 어디에서도 원본 PDF, 추출 텍스트, 다른 사용자의 토큰·평가가 나오지 않는다.
  - `./gradlew test bootJar` 종료 코드 0, 한글 글꼴(fonts-noto-cjk)을 넣은 로컬 컨테이너 기동 후 `python3 scripts/tools.py smoke --port 18080` 종료 코드 0.
  - 3분 녹화 데모: 첫 30초에 문제(이름 노출, 흩어진 피드백)와 결과 화면(버전별 점수 추이)을 보여 준다.
  - `KIRO-USAGE.md`에 단계별 Kiro 기능 사용 기록이 있다.
- 확정 결정(사용자, 2026-11-14):
  - 노출은 순수 무작위(크레딧·평가 의무·직무 매칭 없음, 내 이력서와 내가 이미 평가한 버전만 제외). AI 평가 없음. 입력은 PDF만.
  - 평가자는 레이아웃이 보존된 마스킹 페이지 이미지(PNG)만 본다. 마스킹 텍스트만 보여 주는 방식은 폐기했다. 박스는 렌더링한 이미지에 그린다(PDF 위에 덮으면 텍스트가 남으므로 금지).
  - 원본 PDF는 초안 동안만 미리보기 재생성용으로 임시 보관(최대 24시간)하고 게시 시점에 지운다. 저장하는 것은 주인 전용 추출 텍스트, 게시된 마스킹 PNG, 마스킹 영역 목록이다.
  - 배포 목표는 localhost Docker 데모와 녹화 영상이다. 공개 배포는 필수가 아니다.
  - 평가 방식(항목별 1~5점 평가표 폐기): 평가자는 마스킹 이미지를 눌러 위치별 첨삭 핀(코멘트 1~500자, 페이지 번호 + 0~1 정규화 좌표)을 0개 이상 남기고, 총평(20자 이상)과 총점(1~5 정수)을 필수로 낸다. 제출 전에는 핀을 고치거나 지울 수 있고, 제출은 한 번에 원자적으로 저장되며 이후 수정할 수 없다. 핀은 버전 간에 이월하지 않는다.
  - 화면은 정적 HTML/CSS/JS + JSON API, 차트는 외부 CDN 없이 직접 그린 SVG. 데모 샘플(가상 인물 v1·v2와 핀 포함 평가)은 명시적 버튼으로만 넣고, 실제 평가 장면은 시크릿 창으로 시연한다.
- 알려진 한계: ToUnicode 정보가 없는 글꼴은 자동 마스킹이 빠질 수 있다. 그래서 미리보기 확인이 필수이고, 2순위로 수동 박스를 둔다.
- 열린 질문 모두 확정(2026-11-14): 복구 코드 MVP 포함, 이미지는 구분 없이 전부 가림, 평가자 라벨 버전별, 핀 50개·총평 1000자.
- 2순위(MVP 이후): 페이지 이미지 위에 드래그로 박스를 그리는 수동 마스킹. 이 기능이 생기면 스캔본 PDF를 받는다.
- 범위 밖: AI 평가, OCR, 직무 매칭, 크레딧, 실제 인증(회원가입·로그인), 신고·제재, 원본 PDF 저장·다운로드, 공개 배포, 외부 API 호출.
