# 이게 다 너 잘되라고 하는 소리야

이력서를 고쳐 가며 지원하는 취업 준비자가 **이름과 원문을 드러내지 않고, 익명 평가자에게 이력서 위에 직접 첨삭을 받고, 버전마다 받은 평가를 한곳에 모아 보는** 익명 이력서 평가 서비스.

**Demo:** 녹화 스크립트는 `e2e/demo.spec.cjs`(실행: `e2e/run.sh demo`), 편집·MP4 변환은 `e2e/to-mp4.sh`이며 결과는 `artifacts/demo/demo.mp4`에 생성된다(생성 전에는 파일이 없다). 로컬 실행 방법은 아래 6. 설치와 실행.

## 1. 문제 정의

### 대상 사용자
이력서를 여러 번 고쳐 가며 지원하는 취업·이직 준비자. 특히 이력서를 파일(Typst·워드·PDF)로 직접 관리하며 버전을 쌓아 가는 사람.

### 문제 상황
1. **평가를 많이 받기 어렵다:** 취업 준비자가 이력서를 고칠 때마다(상황) 평가를 부탁할 수 있는 사람은 지인 몇 명뿐이고, 채용 플랫폼의 첨삭 서비스는 이름과 이력서 원문을 그대로 공개해야 해서(상황) 부담스럽고 망설이게 된다(불편).
2. **개인정보를 지우면 디자인을 평가받지 못한다:** 개인정보를 가리려고 텍스트만 복사해 보여 주면(상황) 레이아웃·가독성 같은 이력서 디자인은 평가받을 수 없다(불편).
3. **버전별 평가가 흩어진다:** 이력서를 개인 Git 저장소에서 Typst(.typ)로 작성해 push하고 태그로 릴리즈를 관리하면(상황), 버전은 남지만 각 버전에 받은 피드백은 메신저·메일에 흩어져 어떤 수정이 효과가 있었는지 비교할 수 없고, 버전마다 사본을 만들어 공유하는 일이 피곤하다(불편).

### 기존 방식과 한계
| 기존 방식 | 한계 |
|---|---|
| 지인·스터디에 부탁 | 평가자 수가 적고, 이름이 드러나 솔직한 평가를 받기 어렵다 |
| 채용 플랫폼 첨삭·이력서 공개 | 이름·연락처·원문이 공개된다. 평가 이력이 버전별로 남지 않는다 |
| 텍스트만 복사해 커뮤니티에 올리기 | 개인정보는 손으로 지워야 하고 빠뜨리기 쉽다. 디자인은 평가받지 못한다 |
| Git 저장소 + 태그 릴리즈로 버전 관리 | 버전은 남지만 피드백이 버전에 붙지 않는다. 공유할 때마다 개인정보를 지운 사본을 따로 만들어야 한다 |

### 근거
- **팀원 본인 경험(신지섭):** 개인 Git 저장소에서 이력서를 Typst(.typ)로 작성해 push하고, 태그로 릴리즈(버전)를 관리해 왔다. 버전을 만들 때마다 빌드·태그·공유용 사본 정리를 반복하는 일이 피곤했고, 평가를 많이 받고 싶어도 부탁할 사람이 적어 현실적으로 어려웠다.
- **그 저장소의 실제 기록:** 2026-10-22부터 11-06까지 16일 동안 이력서·포트폴리오 **릴리즈 8개, 태그 20개**를 만들었다. 각 버전에 대한 리뷰·검토 내용은 버전과 분리된 메모 파일 **7개**로 흩어져 있다. 버전은 쌓이지만 "어느 버전에 어떤 평가를 받았는지"는 한곳에서 볼 수 없다.
- 같은 불편을 겪는 대상: 이력서를 버전으로 관리하며 여러 회사에 지원하는 취업·이직 준비자.

### 목표
- 이메일·전화번호·링크·이미지는 자동으로 가리고, 이름·회사·학교는 사용자가 가릴 단어로 지정해 **레이아웃은 그대로 둔** 이력서 페이지 이미지로, 익명 평가자에게 익명 평가를 받게 한다.
- 평가자는 이력서의 **해당 위치를 클릭해 첨삭**하고 총평·총점을 남긴다.
- 주인은 **버전마다 받은 첨삭을 페이지 위에 겹쳐** 보고, 버전별 평균 총점을 비교한다.

## 3. 사용 시나리오

1. 회원가입이나 이름 입력 없이 시작한다. 평가받기·평가하기 화면에 들어가면 익명 토큰이 자동 발급된다.
2. 이력서 PDF를 올리면 이메일·전화·URL·사진이 자동으로 검게 가려진 페이지 미리보기가 나온다. 이름·회사·학교를 가릴 단어로 추가하면 미리보기가 다시 만들어진다.
3. 마스킹을 확인했다고 체크하고 게시한다. 원본 PDF는 이때 서버에서 지워진다.
4. 다른 사용자가 '평가하기'에서 무작위로 받은 이력서 이미지 위를 클릭해 첨삭 핀을 남기고, 총평과 총점(1~5)을 제출한다.
5. 주인은 '내 이력서'에서 버전을 골라 페이지 위에 겹쳐진 모든 핀과 총평·총점을 본다. 이력서를 고치면 새 버전(v2)을 올려 같은 과정을 반복하고, 버전별 평균 총점을 비교한다.

## 4. 기대 효과

| 항목 | 기존 | 이 서비스 |
|---|---|---|
| 평가를 부탁할 수 있는 사람 | 지인 몇 명 | 익명 평가자에게 무작위로 배정(로컬 데모이며 실제 평가자 풀은 검증 전) |
| 공유용 사본 만들기(개인정보 지우기) | 버전마다 손으로 1회 | 0회: 업로드 1회로 자동 마스킹 + 미리보기 확인 |
| 자동으로 가려지는 개인정보 | 0개(수동) | 텍스트 추출이 되는 PDF에서 이메일·전화·URL·이미지 자동(일부 글꼴은 빠질 수 있어 게시 전 미리보기 확인 필수), 이름·회사·학교는 단어 지정. 데모 샘플 이력서 4개 모두에서 4종이 검출됨(`DemoPdfTest`) |
| 디자인 평가 | 텍스트 공유 시 불가 | 레이아웃이 보존된 페이지 이미지로 가능 |
| 버전별 피드백 위치 | 메신저·메일에 흩어짐 | 버전마다 한 화면(핀 오버레이 + 총평·평균 총점) |

## 5. 차별점

- **레이아웃을 지키는 익명화:** 텍스트만 뽑아 공유하는 대신 페이지를 이미지로 렌더링한 뒤 검은 박스를 칠한다. 디자인은 평가받고, 텍스트 레이어가 없어 복사로도 개인정보가 새지 않는다. 게시 전에 서버가 마스킹 영역 픽셀이 실제로 검은지 다시 검사한다.
- **위치를 짚는 첨삭:** "전반적으로 좋네요" 대신 이력서의 특정 위치에 핀을 꽂아 코멘트한다. 핀은 페이지 크기에 대한 비율 좌표로 저장해 화면 크기가 달라도 같은 자리에 보인다.
- **버전 단위 평가 이력:** 평가가 버전에 묶여 쌓인다. Git 태그로 버전만 관리하던 방식에 "버전별 피드백"을 더한다.
- **가입 없는 익명:** 브라우저에 저장된 익명 토큰만 쓴다. 평가자 정보는 주인에게, 주인 정보는 평가자에게 보이지 않는다.

## 6. 설치와 실행

요구 사항: JDK 21 (Gradle Wrapper 포함, 별도 설치 불필요). 외부 API·AI 키 없이 동작한다.

```bash
# 1. 빌드와 테스트
./gradlew test bootJar

# 2. 실행 (127.0.0.1:18080)
SERVER_ADDRESS=127.0.0.1 SERVER_PORT=18080 java -jar build/libs/app.jar
# 브라우저에서 http://127.0.0.1:18080

# (선택) 샘플 데이터 버튼을 켜려면 demo 프로필로 실행
SPRING_PROFILES_ACTIVE=demo SERVER_ADDRESS=127.0.0.1 SERVER_PORT=18080 java -jar build/libs/app.jar

# (선택) Docker 로컬 배포: 한글 글꼴 포함 이미지
docker compose -p kirothon up -d --build
```
- 데이터는 `DATA_DIR`(기본 `./data`)의 H2 파일 DB에 저장된다. Docker 사용법은 [`DEPLOY.md`](DEPLOY.md).
- 데모용 가상 인물 이력서 PDF: `src/main/resources/demo/`.

## 7. 테스트

```bash
./gradlew test          # JUnit 단위·HTTP 통합 테스트 (PDF 추출, 마스킹 영역, 렌더링 픽셀, 업로드·게시, 평가 API, 접근 경계, 동시성)
python3 -B -m unittest discover -s tests   # 개발 도구(scripts/) 테스트
```
